> 本段必须连续保留在最终成片中，不得通过倍速压缩到 2 分钟以内。

## 01:02～01:15　AI 协同段落转场

**画面**

切换标题卡“AI 协同不是一句口号”，展示“发现问题 → 输入 Prompt → AI 分析 → 人工审查 → 修改验证 → Git 留痕”，屏幕角落显示“AI 协同复现 01:02～03:32”。

**配音**

> 接下来是本视频最关键的 AI 协同过程复现。项目不是一次性让 AI 生成全部代码，而是由我发现问题、提出约束、审查方案，再让 AI 协助定位和修改，最后通过运行结果与 Git 提交完成验证。下面展示两条真实发生的修复链。

## 01:15～02:20　案例一：银行家算法被错误推荐为二叉树遍历

### 01:15～01:28　展示问题

**画面**

打开 docs/ai-history/chain-2/01_user_upload_evidence.jpg，放大错误推荐区域；切到旧逻辑代码片段，停留在“遇到第一个关键词立即返回”的位置。

**配音**

> 第一个问题发生在 AI 私教的实验推荐模块。我输入“推导银行家算法”，回答正文里出现了“递归检查”四个字，旧算法按实验列表顺序扫描，在看到“递归”后就提前返回了二叉树遍历，真正的死锁实验甚至没有参与比较。

### 01:28～01:45　现场输入 Prompt

**画面**

切到 AI 对话工具空白会话，将案例一 Prompt 完整粘贴进去；鼠标划过“先解释错误路径、专有词优先、全部实验参与评分、必须给回归用例”四个约束；点击发送。

**此处实际输入**

> 我在 AI 私教输入“推导银行家算法”，回答正确，但推荐卡片却跳到了“二叉树遍历”。请先不要直接改代码。检查旧版 detectRecommendedExperiment 中按数组顺序遇到关键词就立即返回的逻辑，解释为什么回答里的“递归检查”会抢先命中二叉树。然后给出最小且可验证的修复方案：用户问题中的专业考点词必须高于回答正文中的通用词；必须遍历全部实验后选择最高分；不能破坏离线推荐；最后给出“银行家算法”和“二叉树遍历”两个回归测试。

**配音**

> 我没有只说“帮我修一下”，而是把错误输入、错误输出、怀疑位置和验收条件一起交给 AI，并明确要求它先解释原因，再给出能够回归验证的方案。

### 01:45～02:03　展示 AI 分析和人工判断

**画面**

向下滚动 AI 回复，高亮“通用词抢先命中、提问专有词权重 100、全局评分后再选择最高分”；切换 IDE，展示当前 strongKeys、keys 和综合评分代码。

**配音**

> AI 判断这是典型的通用高频词抢先命中。它建议把用户问题与回答正文分开计分：提问中的“银行家”“死锁”等专有词赋予最高权重，正文中的辅助词只做低分补充；同时取消先到先得，遍历全部 25 个实验后再选择最高分。这里我重点审查了权重是否会造成新的跨学科误判，并保留了最低置信度阈值。

### 02:03～02:20　运行验证与 Git 留痕

**画面**

在页面重新输入“推导银行家算法”，展示推荐已变为“死锁：预防、避免与解除”；切到 GitHub Commit db19019，展示提交标题和核心 Diff。

**配音**

> 修改后，同样的提问稳定推荐死锁与银行家算法实验；输入“前序遍历”则仍然正确进入二叉树实验。修复结果对应 Git 提交 db19019，问题、Prompt、代码差异和最终验证形成了完整证据链。

## 02:20～03:18　案例二：网络头像 URL 溢出评论区

### 02:20～02:32　展示问题

**画面**

打开 docs/ai-history/chain-3/01_user_upload_evidence.png，放大评论输入区域的长 URL；在旧代码片段中高亮 currentUserAvatar 直接作为文本输出的位置。

**配音**

> 第二个问题来自研学社区。网络头像保存的是一百多个字符的图片 URL，旧组件却把它直接当成文字塞进 32 像素的圆形容器，导致链接横向穿透并覆盖评论输入框。

### 02:32～02:48　现场输入 Prompt

**画面**

新建第二个 AI 会话，粘贴案例二 Prompt，高亮“统一组件、图片失败降级、覆盖全部头像挂载点、不要只改 CSS”，点击发送。

**此处实际输入**

> 社区评论区出现头像与输入框重叠。当前 currentUserAvatar 可能是一段很长的 http、https 或 data 图片地址，旧代码直接在 composer-avatar 中输出字符串。请先分析为什么单纯增加宽度或 word-break 不是可靠修复，再设计一个统一的 React AvatarBadge：图片地址渲染为 img，加载失败降级为昵称首字，普通文字只显示 1～2 个字符；必须覆盖帖子作者、评论作者、评论输入区和当前身份条，并补充 overflow:hidden 与 flex-shrink:0 防御样式。请列出修改点和验证用例。

**配音**

> 第二次 Prompt 同样写清了数据类型、失败表现和工程约束。我特别强调不能只用 CSS 把问题暂时盖住，而要建立统一头像组件，并处理图片加载失败和离线场景。

### 02:48～03:05　展示 AI 方案和代码落地

**画面**

展示 AI 回复中的根因分析；切换 CommunityHub.jsx，依次展示 isUrl 判断、图片渲染、onError 降级和首字徽章；切换 styles.css，高亮 overflow:hidden、object-fit:cover、flex-shrink:0。

**配音**

> AI 给出的根因与现场一致：这是数据语义错误，不只是尺寸问题。最终落地的 AvatarBadge 会识别 URL 并渲染图片，图片加载失败时自动退化为昵称首字；纯文本头像只保留一到两个字符。容器同时增加溢出隐藏和禁止压缩，四类头像挂载点全部改用同一组件。

### 03:05～03:18　验证与提交

**画面**

打开社区评论区，展示头像、文字和输入框不再重叠；展示图片加载失败的首字降级效果；打开 Commit 3efb9ac。

**配音**

> 刷新后，正常图片、损坏链接和文字徽章都能稳定显示，评论区不再重叠。该修复对应提交 3efb9ac。这里保留的不是一张结果图，而是从问题发现、Prompt 引导、代码修改到结果验证的完整过程。

## 04:05～05:00　实验中的“理论—操作—解释—代码”

**画面**

**配音**

> 每个实验不是一上来就播放动画，而是先告诉学生理论目标、变量含义和每个选项的作用。以五级流水线为例，学生既能看自动演示，也能逐周期推进。每一次操作都会同步改变指令位置、数据通路、文字解释和正式代码高亮。系统不仅告诉学生“变了什么”，还解释“为什么变”，以及该处理对 CPI 或算法复杂度产生什么影响。

## 05:00～05:50　做错真题，一键进入对应实验

**画面**

进入 408 真题大厅，选择 Cache 组相联 Tag 位数题；故意选择错误答案；展示正确答案、考点分析和绿色实验推荐条；点击“立即启动仿真实验推演”；在 Cache 实验中展示题目参数已经带入，并执行一步。

**配音**

> 真题模块不是孤立题库。现在故意做错一道 Cache 地址划分题，系统先给出考点分析，再推荐对应的组相联映射实验。点击后，题目里的地址位数、块大小和相联度直接带入沙盘。学生可以亲眼看到 Tag、组索引和块内偏移怎样产生，用实验验证刚才的公式，而不是背下答案后继续下一题。

> 当学生在实验后仍有疑问，可以继续向 AI 私教追问。这里 AI 不直接代替学生完成操作，而是结合当前考点解释原因，并把下一步验证重新交给实验。在线时可以接入 DeepSeek-R1；没有密钥或断网时，系统自动切换到内置 408 知识图谱，核心学习路径仍然可用。
